# メニュー整理・「問題作成」名称変更 実装計画

## 0. 目的と前提

本書は、現在のナビゲーションと PR #41（merge commit `22c2fde`、構成 commit `2ad0d62`、`08dfa17`、`b0f8710`）を確認したうえで、デスクトップの「その他」にある重複導線を整理し、「作成」というメニュー名を「問題作成」へ明確化するための実装計画を定める。

今回は調査と設計のみを対象とし、React コンポーネント、ルーティング、CSS、E2E を含むアプリケーション実装は変更しない。実装時にも既存 URL、各画面の機能、保存データ、API は変更しない。

## 1. 現状調査

### 1.1 PR #41 で導入されたメニュー階層

PR #41 は、学習対象と横断機能を分離し、次の構成へ整理した。

- デスクトップの共通上部ナビに、主要な学習対象である「詰め将棋」「定跡学習」「次の一手」と、横断機能である「復習」「学習記録」「作成」を配置した。
- 720px 以下では主要 4 項目と「その他」だけを固定下部ナビに表示し、`nav-secondary` の「復習」「学習記録」「作成」を非表示にした。
- `MorePage` に「復習」「学習記録」「作成」「データ出典」を置き、モバイルでも副次導線へ到達できるようにした。
- ホームでは「学習対象」と「学習を支える機能」を分け、後者に「復習」「学習記録」「作成」を置いた。
- 問題編集画面のタイトルを、対象が詰め将棋であることが分かる「詰め将棋問題作成」にした。
- E2E に、共通ナビの階層、`/more` の項目、360px 幅の下部ナビから「その他」を経由する導線の確認を追加した。

この設計によりモバイルの項目数は抑えられた一方、デスクトップでは上部ナビと `/more` の双方に「復習」「学習記録」「作成」が表示され、同じ導線が重複している。

### 1.2 現在の実装

| 表示箇所 | 現在の項目 | 実装箇所 | 補足 |
| --- | --- | --- | --- |
| 共通ナビ（デスクトップ） | ホーム、詰め将棋、定跡学習、次の一手、復習、学習記録、作成、その他 | `frontend/src/App.tsx` | `nav-secondary` はデスクトップで表示される |
| 共通ナビ（720px 以下） | ホーム、詰め将棋、定跡、次の一手、その他 | `frontend/src/App.tsx`, `frontend/src/index.css` | `nav-secondary` は CSS で非表示 |
| その他 | 復習、学習記録、作成、設定、データ出典 | `frontend/src/pages/MorePage.tsx` | 現在は viewport にかかわらず同じ配列を描画する |
| ホームの横断機能 | 復習、学習記録、作成 | `frontend/src/pages/HomePage.tsx` | 共通ナビとは別のホームカード |
| 問題編集画面 | 画面タイトル「詰め将棋問題作成」 | `frontend/src/pages/ProblemEditorPage.tsx` | 詰め将棋の作成・編集だけを提供する |

現在の `/problem-editor` と `/problem-editor/:id` は同じ `ProblemEditorPage` を使用する。互換用の `/editor` も同じ画面へ到達する。編集フォームや API は `TsumeProblem` を対象としており、現時点で次の一手や定跡教材を作成する汎用エディタではない。

PR #41 後に「設定」が `/more` へ追加されている。これは上部ナビと重複しない既存導線であるため、今回の整理では削除・改名せず、デスクトップ／モバイルとも維持する。

### 1.3 現在のテスト

主な回帰テスト候補は `frontend/e2e/shogi-learning.spec.ts` である。

- `home presents learning subjects separately from cross-cutting tools` は、ホームの「学習を支える機能」に「復習」「学習記録」「作成」があることを確認する。
- `main and mobile navigation use the new hierarchy` は、共通ナビに 3 項目が attach され、`/more` にも同じ項目が見えることを確認する。現在は viewport ごとの表示差を十分に分離していない。
- `mobile layout (360px)` 内の `bottom navigation shows primary items and その他 leads to secondary pages` は、モバイル下部ナビの項目数と `/more` の副次項目を確認する。
- `problem editor renders the board editor and required fields` は、「詰め将棋問題作成」という画面タイトルを確認する。
- 設定画面の E2E は `/more` から `/settings` へ遷移しているため、今回の表示条件を追加してもこの導線を壊さない必要がある。

## 2. 今回実装する内容

### 2.1 表示仕様

実装後の表示を次のとおりとする。「設定」は今回の変更対象ではないが、現行導線を維持するため表に含める。

| 項目 | デスクトップ上部ナビ | デスクトップ「その他」 | モバイル下部ナビ | モバイル「その他」 |
| --- | :---: | :---: | :---: | :---: |
| 復習 | 表示 | **非表示** | 非表示 | 表示 |
| 学習記録 | 表示 | **非表示** | 非表示 | 表示 |
| 問題作成 | 表示（「作成」から改名） | **非表示** | 非表示 | 表示（「作成」から改名） |
| 設定 | 非表示 | 表示（現状維持） | 非表示 | 表示（現状維持） |
| データ出典 | 非表示 | 表示 | 非表示 | 表示 |

これにより、デスクトップでは上部ナビと「その他」の重複をなくし、「その他」には少なくとも「データ出典」を残す。現行の非重複項目「設定」も残す。モバイルでは下部ナビの主要 5 項目構成を変えず、「その他」から「復習」「学習記録」「問題作成」「設定」「データ出典」へ到達できる状態を維持する。

### 2.2 名称変更

利用者向けメニュー名称「作成」を「問題作成」へ統一する。対象は少なくとも次の 3 箇所である。

1. `frontend/src/App.tsx` のデスクトップ上部ナビ。
2. `frontend/src/pages/HomePage.tsx` の「学習を支える機能」カード。
3. `frontend/src/pages/MorePage.tsx` のモバイル向けカード。

説明文「詰め将棋問題を作成・編集」は現状でも機能範囲を正しく示すため維持できる。`ProblemEditorPage` の `<h1>詰め将棋問題作成</h1>` も変更しない。メニューは入口となる機能カテゴリを「問題作成」と表現し、遷移先では現在作成可能な問題種別を具体的に「詰め将棋問題作成」と表現する。

### 2.3 デスクトップ／モバイルの出し分け

`MorePage` の viewport ごとの出し分けは、共通ナビが既に採用している 720px breakpoint と CSS のレスポンシブ表示方針に合わせる。実装案は次のとおりである。

- 「復習」「学習記録」「問題作成」のカードへ、モバイルの「その他」でのみ表示することを表す class を付ける。
- デフォルト（デスクトップ）ではその class を `display: none` とし、既存の `@media (max-width: 720px)` 内で表示へ戻す。
- 「設定」「データ出典」は viewport にかかわらず表示する。
- `window.innerWidth` や render 中の `matchMedia` による条件分岐は導入せず、共通ナビと同じ CSS breakpoint を単一の判断基準とする。resize 時の React state、listener、初期描画差を新たに持ち込まない。
- 非表示カードをアクセシビリティツリーにも残さないよう `display: none` を使用し、E2E では単に DOM の有無ではなく `toBeHidden()`／`toBeVisible()` で表示状態を検証する。

class 名は既存の `.nav-secondary` と混同せず、`MorePage` の用途が分かる `.more-mobile-only` などを候補とする。将来項目が増えた場合も、「配列から削除」ではなく表示対象を明示できる構造にする。

### 2.4 既存ルート・機能の維持

以下は変更しない。

- `/review`、`/history`、`/problem-editor`、`/problem-editor/:id`、`/editor`、`/licenses`、`/more`、`/settings` を含む全 route 定義。
- `NavLink`／`Link` の遷移先、および current-page 判定。
- `ProblemEditorPage` の詰め将棋作成、編集、検証、保存、削除機能と API。
- ホームの「学習対象」「学習を支える機能」という情報設計。
- モバイル下部ナビの主要 4 項目＋「その他」という項目数、順序、720px breakpoint。
- 「設定」と「データ出典」の既存導線。

## 3. 対象ファイル候補と実装手順

### 3.1 対象コンポーネント／スタイル

| ファイル | 予定する変更 |
| --- | --- |
| `frontend/src/App.tsx` | 上部ナビの「作成」を「問題作成」に変更する。route 定義は変更しない |
| `frontend/src/pages/HomePage.tsx` | 横断機能カードの「作成」を「問題作成」に変更する |
| `frontend/src/pages/MorePage.tsx` | 「作成」を「問題作成」に変更し、復習・学習記録・問題作成をモバイル限定表示として識別する |

`frontend/src/pages/ProblemEditorPage.tsx` は確認対象だが、画面タイトルを維持するため変更対象にはしない。

### 3.2 テストファイル候補

中心となる変更候補は `frontend/e2e/shogi-learning.spec.ts` である。実装仕様を viewport 別に明示するため、既存のナビテストを次の観点で整理する。

#### デスクトップ E2E

明示的なデスクトップ viewport（例: 1280px 幅）で次を確認する。

1. 共通上部ナビに「復習」「学習記録」「問題作成」が visible である。
2. 旧名称「作成」の exact match が共通上部ナビに存在しない。
3. 「問題作成」をクリックすると既存の `/problem-editor` へ遷移する。
4. 遷移先の画面タイトルが引き続き「詰め将棋問題作成」である。
5. `/more` では「復習」「学習記録」「問題作成」が hidden である。
6. `/more` では「設定」「データ出典」が visible で、「データ出典」から既存の `/licenses` へ遷移できる。

#### モバイル E2E

既存の 360×740 viewport suite で次を確認する。

1. 下部ナビが「ホーム」「詰め将棋」「定跡」「次の一手」「その他」の 5 項目を維持する。
2. 「復習」「学習記録」「問題作成」は下部ナビでは hidden である。
3. 「その他」へ遷移すると「復習」「学習記録」「問題作成」「データ出典」が visible である（既存の「設定」も visible）。
4. 各カードの `href` がそれぞれ `/review`、`/history`、`/problem-editor`、`/licenses` のままである。
5. 「問題作成」から `/problem-editor` へ遷移し、「詰め将棋問題作成」が表示される。
6. 主要ナビと `/more` で横スクロールが発生しない。

#### 既存 E2E の期待値更新

- ホームの横断機能テストの期待値を「作成」から「問題作成」へ変更する。
- PR #41 由来の `main and mobile navigation use the new hierarchy` は、デスクトップとモバイルの責務を別 test／describe へ分けるか、viewport と visible/hidden の期待を明示する。
- モバイル「その他」の見出し期待値を「作成」から「問題作成」へ変更する。
- 問題編集画面の見出し期待値「詰め将棋問題作成」は変更しない。
- `/more` 経由で設定画面を確認する既存テストが、デスクトップでも引き続き通ることを確認する。

### 3.3 実装順序

1. E2E の desktop/mobile 表示仕様と名称期待値を先に更新し、変更前に意図した差分で失敗することを確認する。
2. `App.tsx`、`HomePage.tsx`、`MorePage.tsx` の名称を「問題作成」へ更新する。
3. `MorePage` の 3 項目へモバイル限定 class を付け、`index.css` の既存 breakpoint で表示を切り替える。
4. desktop/mobile E2E を実行し、表示、非表示、リンク遷移、画面タイトル、横幅を確認する。
5. frontend の lint、build、Vitest 全体、Playwright 全体を品質ゲートとして実行する。

実装時の確認コマンド候補は次のとおりである。

```bash
cd frontend
npm run lint
npm run build
npx vitest run
npm run e2e
```

## 5. 将来検討事項

今回の名称変更は、現在の詰め将棋作成機能を「作成」より明確に案内しつつ、問題種別の拡張余地を残すものである。次の内容は別途要件定義・情報設計を行う。

1. 次の一手の問題を作成・編集する機能。
2. 詰め将棋と次の一手を横断して扱う問題作成機能。
3. 定跡ライン、分岐、解説、学習用手順など、定跡学習用コンテンツを作成・編集する機能。
4. 対象が個別の「問題」を越えて定跡教材等へ広がった場合、メニュー名称を「問題作成」から「教材作成」へ変更すること。
5. 複数種別を扱う必要が生じた段階で、問題作成／教材作成のトップ画面と、詰め将棋・次の一手・定跡などの種類別エディタを持つ route／画面構成にすること。

トップ画面や route 階層は、具体的な第 2 種別を実装するときに URL の後方互換、共通メタデータ、一覧、権限、保存 API を含めて判断する。今回、将来構成を先取りした空画面や抽象化は追加しない。

- `ProblemEditorPage` の画面タイトル変更、汎用エディタへの改修、フォームや盤面操作の変更。
- 次の一手問題、定跡ライン、分岐、解説、学習手順の作成機能。
- 問題作成／教材作成トップ画面や種類選択 UI の新設。
- 「教材作成」への名称変更。
- バックエンド API、schema、DB migration、既存データの変更。
- モバイル下部ナビの項目数、主要項目、順序、breakpoint の再設計。
- ホームの「学習対象」「学習を支える機能」の再編。
- 「設定」「データ出典」導線の削除や別画面への移動。
